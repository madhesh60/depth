## What it shows

| the agent decides alone | it asks a person | only a person does |
|---|---|---|
| how hard to look (the goal and budgets → standard or look-harder), whether its promise applies, which seabed measurement to trust, where pins go, the queue order, which passes are worth boat time | inspect · recover · re-survey · full review · public sharing — `request_human_approval`, with a rationale | approve or decline (name + PIN; five wrong PINs lock the address out), confirm or reject a card, mark recovered / not found — every decision re-plans |

- No MCP tool can decide (row 1): of the three that are not read-only, two compute (`analyze_frame`, `run_survey`) and the third only files a request.
- The agent cannot approve its own request through the HTTP API either: without the PIN it is refused (403).
- A person's approval becomes a work order the agent can read back; downstream consoles receive it as the signed `approval.decided` webhook. DEPTH itself never dispatches.
- Here the person's click is scripted (the same endpoint the studio's Approvals panel calls); in the demo a person presses *Approve* in the studio.
