Workload `product` = what `/api/analyze` runs per frame in the standard look (1 forward pass): JPEG decode → Stage 1 (canonicalise + bottom track) → YOLO11 via `cv2.dnn` → evidence + calibrated tiers → overlay + JPEG encode; rows labelled `…_lh` are the look-harder mode (+ the 2×2 tile pass, 5 forward passes), which an idle server's analyze picks when its 2-s budget allows. `cv` = the product path's OpenCV image ops without the network. `survey` = a raw sonar recording end to end (read → sonogram → seabed cross-check → frame agent → plan). A run counts as **COOL** only if `cv2.__file__` is under `/opt/cool` (provenance, not "KleidiCV in the build", which the stock Arm wheel also reports). The OpenCV column also names the `cv2.dnn` engine the run used: `auto` in runs from before STUDY-20 recorded it (ENGINE_AUTO, identified as the new engine), `new` / `classic` after; since 2026-10-23 the server and the benchmark measure both engines on the machine and keep the faster one with the same answers (`DEPTH_DNN_ENGINE=fastest`, [`dnn_engine.md`](dnn_engine.md)).
